# Запуск на Android-телефоне (USB)

## 1. Почему не запускается на Windows и Edge

- **Windows (desktop):** нужна установленная Visual Studio с workload «Desktop development with C++». Без неё `flutter run -d windows` выдаёт ошибку про toolchain. Если нужен только телефон — можно не ставить.
- **Edge:** запуск веба в Edge делается так: `flutter run -d edge`. Если не запускается — попробуйте Chrome: `flutter run -d chrome`.

## 2. Подключить телефон и чтобы Flutter его увидел

Сейчас `adb devices` показывает пустой список — телефон не виден. Нужно:

1. **На телефоне**
   - Настройки → О телефоне → 7 раз нажать «Номер сборки» (включится «Для разработчиков»).
   - Настройки → Для разработчиков → включить **Отладка по USB**.
   - Подключить кабель к ПК.
   - При запросе «Разрешить отладку по USB?» нажать **Разрешить** (можно поставить «Всегда с этого компьютера»).

2. **Режим USB на телефоне**
   - После подключения в шторке уведомлений выбрать режим USB: **Передача файлов (MTP)** или **PTP**, не «Только зарядка».

3. **Кабель и порт**
   - Кабель должен поддерживать данные (не только зарядку). Лучше пробовать другой кабель/порт USB.

4. **Драйвер (Windows)**
   - На некоторых телефонах Windows сама ставит драйвер. Если устройство не появляется, установите драйвер с сайта производителя или включите в настройках разработчика «Установка по USB» (если есть).

5. **Проверка**
   ```bash
   # adb из Android SDK (путь из flutter doctor)
   C:\Users\HONOR\AppData\Local\Android\sdk\platform-tools\adb.exe devices
   ```
   Должна появиться строка с id устройства (не «unauthorized»).

6. **Если в списке «unauthorized»**
   - На телефоне снова подтвердить «Разрешить отладку по USB».
   - Можно выполнить: `adb kill-server`, затем снова `adb devices` и снова разрешить на телефоне.

## 3. Лицензии Android SDK (если Flutter ругается при сборке)

В `flutter doctor` было предупреждение про лицензии и cmdline-tools:

1. В **Android Studio**: Settings → Appearance & Behavior → System Settings → Android SDK → вкладка **SDK Tools**.
2. Поставить галочки: **Android SDK Command-line Tools (latest)**, **Android SDK Platform-Tools**.
3. Apply → OK.
4. В терминале:
   ```bash
   flutter doctor --android-licenses
   ```
   Вводить `y` и Enter для принятия лицензий.

После этого `flutter run` сможет собирать приложение под Android.

## 4. Запуск на телефоне

Когда устройство видно в `flutter devices`:

```bash
cd art_front
flutter run
```

Если устройств несколько, Flutter спросит, на какое ставить. Или укажите устройство явно:

```bash
flutter run -d <device_id>
```

`device_id` можно посмотреть в выводе `flutter devices`.

## 5. Бэкенд при запуске на реальном устройстве

На **эмуляторе** приложение по умолчанию стучится на `http://10.0.2.2:8000` (ваш ПК).

На **реальном телефоне** `10.0.2.2` не подойдёт. Телефон и ПК должны быть в одной Wi‑Fi сети, а в коде нужно указать IP вашего компьютера.

**Вариант А — передать IP через dart-define (рекомендуется)**

```bash
flutter run -d <device_id> --dart-define=API_BASE_URL=http://192.168.1.100:8000
```

Где `192.168.1.100` — IPv4 вашего ПК в той же Wi‑Fi.

**Вариант Б — один раз подставить IP в коде**

В `lib/main.dart` после `WidgetsFlutterBinding.ensureInitialized();` добавьте (подставьте свой IP):

```dart
if (!kIsWeb) {
  api_platform.initApiConfigForPlatform();
  // Реальное устройство в одной Wi‑Fi с ПК — укажите IP ПК, на котором крутится бэкенд:
  // ApiConfig.baseUrlOverride = 'http://192.168.1.100:8000';
  _setSystemUIOverlay();
}
```

Раскомментируйте строку с `ApiConfig.baseUrlOverride` и замените `192.168.1.100` на IP вашего ПК (в PowerShell: `ipconfig`, смотреть IPv4 в активном Wi‑Fi-адаптере).

**Вариант В — бэкенд слушает все интерфейсы**

На ПК запускайте бэкенд так, чтобы он слушал `0.0.0.0:8000`, а не только `127.0.0.1`. Тогда с телефона будет доступ по IP этого ПК в сети.

---

Кратко: включите отладку по USB, разрешите её на телефоне, выберите режим «Передача файлов», при необходимости установите cmdline-tools и примите лицензии — после этого `flutter run` должен предложить телефон и запустить на нём приложение.
